# Таксономия космических инцидентов ИБ (версия 1.0.0, срез данных: 2026-10-24)

Документ версионируется вместе с кодом. Любое изменение справочников классификаторов
требает увеличения `taxonomy_version` в `taxonomy/classifiers.csv` и в БД.

## 1. Критерии включения события в базу (inclusion criteria)

Событие включается в базу, если выполнены **все** условия:

- **C1 (Космический контекст).** Затронут хотя бы один сегмент космической системы:
  КА (бортовой сегмент), сегмент TT&C, наземные станции (ground segment), каналы связи
  (uplink/downlink/crosslink), цепочка поставок ПО/Аппаратного обеспечения КА,
  операторские IT-системы, непосредственно влияющие на выполнение миссии.
- **C2 (Инцидент ИБ).** Событие относится к одному из классов: подтверждённая кибератака,
  эксплуатация уязвимости, компрометация данных/доступов, глушение/спуфинг/перехват
  сигналов (jamming/spoofing/meaconing), а также *активно эксплуатируемая* уязвимость
  космического стека (KEV-класс по аналогии CISA KEV). Простое упоминание темы «космос и
  кибербезопасность» без конкретного события — НЕ инцидент.
- **C3 (Открытость).** Есть минимум одна публичная первичная ссылка (advisory, реестр CVE,
  официальный релиз оператора/агентства).
- **C4 (Верификация).** Для статуса `verified` требуется **минимум два независимых
  источника** (независимость: разные организации, разные домены, отсутствие заимствования).
  Один источник → статус `single_source`; непроверяемые утверждения сторон конфликта →
  `disputed`.

## 2. Оси классификации

### 2.1 Целевой сегмент (`target_segment`)
| Код | Название | Примеры |
|---|---|---|
| SEG-SPACE | Бортовой сегмент КА | ПО БРЭО, телеметрия, OBC |
| SEG-TTC | Сегмент TT&C | команды управления, МКС-каналы |
| SEG-GS | Наземные станции / DSN-подобные | антенны, модемы, серверы станций |
| SEG-COMMS | Спутниковая связь (payload) | VSAT, Ku/Ka-транспондеры |
| SEG-IOT | Космический IoT / CubeSat | малые КА, наземные шлюзы IoT |
| SEG-SUPPLY | Цепочка поставок | вендоры ПО, обновления прошивок |
| SEG-OPS | Корпоративный IT оператора | сети, учётные записи |
| SEG-GROUND-OTHER | Прочая инфраструктура | навигационные сервисы (GNSS) |

### 2.2 Орбита / класс миссии (`orbit_class`)
LEO, MEO, GEO, HEO/Molniya, DeepSpace, Suborbital, Ground-only (для SEG-GS/SEG-OPS без привязки к КА), Unknown.

### 2.3 Вектор атаки (`attack_vector`) — маппинг на MITRE ATT&CK for ICS / Space MITRE ATLAS / VERIS
| Код | Название | ATT&CK / ATLAS | VERIS family |
|---|---|---|---|
| V-JAM | Глушение сигнала (uplink/downlink/GNSS) | ATLAS: A0054 Jam signaling | Impact |
| V-SPF | Спуфинг / meaconing GNSS или команд | ATLAS: A0053 Spoof GNSS | Malware? нет → Impact/Skimming |
| V-INT | Перехват/анализ телеметрии, сниффинг | ATLAS: Collection in Space | Eavesdropping |
| V-UPL | Несанкционированный uplink / перехват управления | ATLAS: Hijack SW, Command injection | Intrusion |
| V-MAL | Вредонос на наземной инфраструктуре | T1059 и пр. | Malware |
| V-EXP | Эксплуатация уязвимости (CVE) бортового/наземного ПО | T1190 | Exploit Vulnerability |
| V-CRED | Компрометация учётных данных / доступа | T1078 | Unauthorized Error |
| V-SUP | Атака на цепочку поставок (SW/HW) | ATLAS: Compromise supply chain | Third-party Software |
| V-DOS | Отказ услуг (DDoS станций/сервисов) | ATLAS: DDoS services | Availability DoS |
| V-INS | Инсайдерская угроза | T1091 | Intrusion + Social Engineering |
| V-PHISH | Фишинг против персонала оператора/вендора | T1566 | Social Engineering |
| V-UNAUTH-DISC | Несанкционированный доступ/раскрытие данных миссии | ATLAS: Data from information repositories | Data Breach |

### 2.4 Воздействие на миссию (`impact_level`, шкала 0–5)
0 — нет эффекта; 1 — деградация сервиса; 2 — потеря части данных/временный отказ;
3 — компрометация данных или временная потеря управления; 4 — длительная потеря миссии/КА;
5 — безвозвратная потеря КА или критический ущерб безопасности полёта.

### 2.5 Уровень достоверности (`confidence`)
`verified` (≥2 независимых источника), `single_source`, `disputed` (противоречивые заявления),
`rumor` (не подтверждён; в аналитику не входит, хранится для полноты корпуса).

### 2.6 Тип КА (`sat_type`)
Коммуникационный, Навигационный, ДЗЗ, Научный, Военный/Разведывательный, Кубсат/IoT,
Пилотируемый, Платформа/Ретранслятор, Unknown.

## 3. Согласование с внешними стандартами
- **Space MITRE ATLAS** — векторы, связанные с космическим сегментом (V-JAM, V-SPF, V-UPL, V-INT).
- **MITRE ATT&CK (Enterprise/ICS)** — векторы наземного/корпоративного сегмента.
- **VERIS/CVE** — атрибуты последствий и идентификаторы уязвимостей.
- **ESA Space Security Baseline / NIST SP 800-171 / ISO 27001** — рекомендации по защите (этап 5).

## 4. Known limitations (честно фиксируются)
- Открытые данные смещены: новостной цикл ≠ реальная частота инцидентов; часть событий
  никогда не предаётся гласности (underreporting bias).
- По сегментам LEO CubeSat / космический IoT публичная статистика крайне скудна — это
  отражается в результатах как low-N, а не как «низкий риск».
- Заявления сторон геополитических конфликтов о глушении/спуфинге помечаются `disputed`
  и выносятся в отдельный слой анализа.
